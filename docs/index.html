Conector MISP — Guía de configuración

Última actualización: 2026-07-24

¿Qué es y para qué sirve?

El conector MISP permite que el agente de Ruvic intercambie indicadores de amenaza (threat intel) con tu instancia de MISP: puede buscar un indicador de compromiso (IOC), crear un evento y agregar un atributo a un evento existente. Una vez configurado, puedes pedirle al agente cosas como:

  • "Busca si la IP 45.33.22.11 ya está registrada como IOC en MISP."
  • "Crea un evento por la campaña de phishing detectada en finanzas."
  • "Agrega este hash SHA256 como atributo al evento 123."

Operaciones soportadas:

Operación Qué hace
search_ioc Busca un indicador de compromiso por su valor (IP, dominio, hash, URL, etc.), con filtro opcional por tipo
create_event Crea un nuevo evento de amenaza (con nivel de riesgo, distribución y estado de análisis)
add_attribute Agrega un atributo (IOC) a un evento existente, con categoría y marca opcional para IDS/IPS
Este conector SÍ escribe A diferencia de conectores de solo lectura, `create_event` y `add_attribute` crean datos reales y permanentes en tu instancia de MISP. No es de solo consulta.

Prerrequisitos

  • Una instancia de MISP accesible por HTTPS (propia, en la nube o imagen oficial misp/misp-docker).
  • Acceso administrativo a MISP (rol Site Admin u Org Admin), solo durante la configuración inicial, para crear el rol personalizado y el usuario de servicio.
  • Acceso de red desde la plataforma Ruvic a la instancia de MISP (host y puerto alcanzables por HTTPS).
  • La URL base de tu instancia de MISP (ej. https://misp.empresa.com).

Configuración en el fabricante

Vas a crear un rol personalizado de mínimo privilegio y un usuario de servicio dedicado para Ruvic. No reutilices tu propio usuario ni un rol con permisos de administración: un usuario dedicado permite auditar la actividad del agente y limitar el acceso al mínimo necesario.

  1. Crea el rol personalizado. Ve a Administration → Roles → Add Role. Crea un rol nuevo (ej. ruvic-connector) y habilita únicamente Perm: Auth (permite autenticarse vía API con una Auth Key) y Perm: Add (permite crear eventos y agregar atributos). Deja desactivados todos los demás permisos, en particular Perm: Site Admin, Perm: Sync, Perm: Audit y Perm: Delegate.
    [ Captura: formulario de Administration → Roles con Perm: Auth y Perm: Add marcados — reemplazar por assets/img/misp-role.png ]
  2. Crea un usuario de servicio dedicado. Ve a Administration → Users → Add User. Crea un usuario nuevo (ej. ruvic-connector@empresa.com) que se use exclusivamente para este conector, no un usuario personal.
  3. Asigna el rol al usuario de servicio. En el formulario del usuario, selecciona como Role el rol personalizado creado en el paso 1 (ruvic-connector) y guarda.
  4. Genera la Auth Key del usuario de servicio. Inicia sesión como el usuario de servicio (o pide a un administrador que la genere en su nombre) y ve a Event Actions → Auth keys → Add authentication key. Copia la Auth Key generada de inmediato: MISP solo la muestra una vez.
    [ Captura: Event Actions → Auth keys → Add authentication key — reemplazar por assets/img/misp-authkey.png ]
  5. Anota los datos para el formulario de Ruvic. Guarda la URL base de tu instancia (ej. https://misp.empresa.com) y la Auth Key generada. Los necesitarás en la siguiente sección.

Permisos requeridos

Principio de mínimo privilegio: el rol del usuario de servicio solo necesita estos dos permisos. No otorgues roles de administración ni sincronización.

Permiso Para qué sirve
Perm: Auth Permite autenticarse en la API REST de MISP mediante la Auth Key. Requerido para toda operación del conector.
Perm: Add Permite crear eventos (create_event) y agregar atributos a eventos existentes (add_attribute).
No otorgues estos permisos Perm: Site Admin (administración total de la plataforma), Perm: Sync (sincronización con otras instancias MISP) y Perm: Audit (acceso a logs de auditoría) no son necesarios para las operaciones del conector y amplían innecesariamente el impacto de una Auth Key comprometida.

search_ioc funciona con la búsqueda de atributos (/attributes/restSearch), disponible para cualquier usuario autenticado con Perm: Auth sobre los eventos visibles para su organización; no requiere permisos adicionales.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta MISP y pulsa Configurar. Diligencia el formulario (modo de autenticación Auth Key) con los valores obtenidos en la sección anterior:

Campo del formulario Valor
URL base de MISP URL completa de tu instancia, con esquema (ej. https://misp.empresa.com)
Auth Key La Auth Key generada en el paso 4 de la sección anterior. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Verificar certificado TLS Activado por defecto. Desactívalo solo para instancias con certificado autofirmado en entornos de prueba
Timeout de conexión (segundos) Opcional; 15 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a tu instancia de MISP y confirmará que la Auth Key y la red funcionan.

[ Captura: formulario del conector MISP en Settings → Conectores — reemplazar por assets/img/misp-form.png ]

Verificación

  1. Test de conexión exitoso. El botón Probar conexión debe responder con éxito (consulta la versión del servidor MISP). La tarjeta del conector cambia a estado Configurado.
  2. Prueba mínima con el agente. Abre una conversación nueva con el agente y pídele:
    "Busca en MISP si hay algún IOC registrado con el valor 8.8.8.8."
    El agente debe responder con los resultados reales de tu instancia (o indicar que no hay coincidencias). Si lo hace, el conector quedó operativo de punta a punta. Evita pedirle que cree eventos o atributos de prueba en una instancia productiva.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Auth Key inválida o sin permiso suficiente" (error 401/403) La Auth Key es incorrecta, expiró o fue revocada, o el rol del usuario de servicio no tiene Perm: Auth. Genera una nueva Auth Key desde el perfil del usuario (Event Actions → Auth keys) y actualízala en el formulario de Ruvic.
"No se pudo alcanzar MISP" (timeout de red) La plataforma Ruvic no alcanza el host/puerto de MISP. Verifica que la URL base sea correcta y accesible por HTTPS desde fuera de tu red interna, revisa el firewall y aumenta el Timeout de conexión si la instancia responde lento.
Error al agregar un atributo: el evento no existe add_attribute requiere un event_id válido, obtenido del resultado de create_event o de una búsqueda previa. Verifica que el evento exista y sea visible para el usuario de servicio.
Error de datos: tipo de atributo inválido El type_ indicado no coincide con el vocabulario controlado de MISP. Usa tipos válidos como ip-dst, ip-src, domain, hostname, url, md5, sha1, sha256, email-src.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío (URL base o Auth Key). Ábrelo de nuevo y completa ambos campos; luego pulsa Probar conexión.

Preguntas frecuentes y notas de seguridad

¿El agente puede crear datos reales en MISP?

Sí. A diferencia de conectores de solo lectura, create_event crea eventos reales y add_attribute agrega atributos reales y permanentes a tu instancia. El agente debe confirmar contigo antes de ejecutar estas operaciones si no fueron pedidas explícitamente. Usa siempre distribution=0 (solo tu organización) salvo que quieras compartir el evento más ampliamente.

¿Dónde queda guardada la Auth Key?

Como secreto cifrado en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica "definida". Para cambiarla, genera una nueva Auth Key en MISP y pégala en el formulario del conector; para conservarla al editar otros campos, deja el campo vacío.

Rotación de la Auth Key

Recomendado cada 90 días o según tu política: genera una nueva Auth Key desde el perfil del usuario de servicio (Event Actions → Auth keys → Add authentication key), revoca la anterior, actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la Auth Key se compromete?

  1. Revoca la Auth Key comprometida de inmediato desde Event Actions → Auth keys en el perfil del usuario de servicio, o desactiva el usuario en Administration → Users.
  2. Revisa los logs de auditoría de MISP para detectar eventos o atributos creados sin autorización.
  3. Genera una nueva Auth Key y actualízala en el formulario del conector de Ruvic.
Buenas prácticas Usa siempre un usuario de servicio dedicado con un rol de mínimo privilegio (Perm: Auth + Perm: Add únicamente); nunca otorgues Perm: Site Admin, Perm: Sync ni Perm: Audit al usuario del conector; y no compartas la Auth Key por canales no seguros.
